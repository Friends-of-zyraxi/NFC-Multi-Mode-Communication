# 屏幕共享

第一版实现一对一屏幕镜像。已有端对端连接时可直接进入，也可通过 NFC 近场选择设备和交付邀请，画面由 Nearby Connections 传输。邀请方、发现方与画面发送方互相独立，任意一端都可以提出投屏方向。

## 从现有端对端连接进入

1. 端对端连接成功后，一端点击“进入屏幕共享”，对方页面显示邀请，由用户点击“接受并进入屏幕共享”。此入口不检查 NFC 硬件或 NFC 开关。
2. 连接回调由应用级 `RecordNearbyLink` 持有，Activity 以弱引用订阅普通记录事件。端对端新建连接使用 `P2P_POINT_TO_POINT`。投屏服务接管同一端点的控制消息与 STREAM 回调，不重新广播、搜索、连接或调用 `acceptConnection`。
3. 双方从本次 Nearby 连接的原始认证令牌派生一致的会话标识和密钥，交换认证消息。认证早于对方页面和服务绑定到达时，最多暂存两条认证消息；尚未确认接管时拒绝视频数据。
4. 双方核对相同的 Nearby 验证码并分别点击确认。派生会话本身不能替代人工核对；两端均确认后才能选择投屏方向或接收视频。
5. 一方未进入或未完成验证码确认，2 分钟后结束本次连接。确认后沿用下方的方向协商、系统录屏授权及视频流程。
6. “结束共享”保留当前投屏连接以便重新选择方向；“断开”、返回退出投屏页、通知栏停止或对方断开时，会一并结束所复用的端对端连接，普通记录通信需重新连接。

普通记录 BYTES 与投屏控制 BYTES 分流，避免进入投屏时尚未收完的记录被误判为损坏的视频协议。进入投屏后暂停主动发送普通记录。

自动化测试覆盖直接进入按钮、验证码确认界面、同一端点的回调交接、提前到达的认证消息、普通记录分流、过期交接对象拒绝，以及断开后迟到的成功回调不会恢复旧连接。

## 通过 NFC 建立连接

1. 邀请方生成随机会话 ID 和 256 位邀请密钥，广播公开会话 ID，将邀请编码为 NDEF 记录交给 HCE。
2. 加入方从 NFC 获取邀请，仅发现同一服务、同一会话 ID 的端点。邀请在生成 3 分钟后失效，过期时清除广播及 HCE 内容。
3. Nearby 先建立临时传输连接。双方用邀请密钥计算 HMAC-SHA256，输入包含协议版本、会话 ID、双方不同的角色标识和 Nearby 原始认证令牌。验证完成前拒绝方向协商和视频数据，认证超时则断开。
4. 验证后停止广播、发现和 HCE 邀请，仅保留当前端点。邀请不能用于再次接入当前连接；邀请密钥不进入广播名称或日志。
5. 一端提出投屏方向，另一端确认。同时提出方向时，以邀请方的请求为准；请求或录屏准备超过 2 分钟则取消，可重新选择。
6. 发送方点击授权，在每次新的共享中获取系统 MediaProjection 授权。授权 Intent 不持久化，也不复用。用户可选完整屏幕或系统支持的单个应用。
7. 发送方启动媒体投影前台服务，创建一次 VirtualDisplay，编码 AVC 并发送单条 Nearby STREAM。方向变化需先结束当前共享，再确认新方向并获取新的录屏授权。
8. 结束共享会取消视频流、释放采集和编解码资源，保留已认证连接；断开、通知栏停止、移除任务或进程终止后清理整个会话。

## NFC 记录

第一条记录使用 MIME `application/vnd.io.github.zyraxi21.nfc.screen`，UTF-8 JSON 载荷如下：

```json
{"v":1,"session":"UUID","secret":"Base64URL 编码的 32 字节随机密钥","expires":1793577600000}
```

第二条为当前构建包名的标准 Android Application Record。动态邀请单独生成，不混入普通记录列表，也不提供持久写入标签的入口。应用内读卡页仅解析会话摘要、有效期及手动加入操作，原始载荷仍可按需查看。

标准系统唤起由独立的 `NfcDispatchActivity` 接收。Android 17 及以上用 `DISPATCH_NFC_MESSAGE` 保护该入口；桌面 Activity 保持正常启动权限。Android 17 之前通过版本化资源使用空权限。系统未启动过或强行停止的应用、厂商钱包接管标准 HCE 路由等情况，均需在目标设备上验证。应用内的“碰一碰加入”支持私有 AID 读取。

临时邀请不跨进程恢复。普通模拟卡的数据仍按原有方式持久化。

## 视频传输

- Nearby 策略：NFC 和普通端对端新建连接均使用 `P2P_POINT_TO_POINT`，投屏入口复用已有端点。两者进入同一套方向协商与视频编解码流程。两台设备需升级到同一版本后重新建立连接，实际无线吞吐需实测。
- 编码：AVC / H.264，Surface 输入，目标 30 fps、无 B 帧。按原始采集宽高选择支持的编码器，优先硬件编码，尺寸按该编码器要求向上对齐；不主动缩小画面。不支持原始尺寸时明确提示。帧率和码率均受所选编码器能力约束。
- 初始目标码率按 `宽 × 高 × 帧率 × 0.18` 计算，限定在 8—40 Mbit/s 后再受编码器码率范围约束；接收反馈迟缓时降低码率，应用正常调节下限为 1 Mbit/s。发送页展示编码尺寸、目标码率与帧率，这些数值不等于实测无线吞吐。
- 控制消息使用 BYTES，包括认证、方向请求、确认、停止及关键帧请求。
- 单个 STREAM 包含固定魔数、版本、共享 ID，随后顺序写入尺寸、SPS/PPS 和带时间戳的帧。尺寸和视频帧在同一条流内，避免 BYTES 与 STREAM 之间的顺序不确定性。
- 协议支持单边最多 8192 像素、总像素最多 33,554,432 的尺寸，每帧最多 8 MiB，参数集最多各 64 KiB；接收端先检查长度，再分配缓冲区。正常传输最多保留四帧等待接收确认，窗口满时丢弃过时画面并等待新的关键帧；旋转和显示 Surface 重建时重置窗口。确认迟缓时降低码率，不再因为固定 15 秒阈值中断慢速共享；连接错误仍由 Nearby 及流读取错误处理。
- 网络读取和解码分别运行，解码线程每 10 ms 排空输出，避免等待网络下一包时已解码画面滞留；临时离开接收页时继续确认已丢弃的帧，保持传输可恢复。
- 源端内容尺寸变化时调整同一个 VirtualDisplay，并更换编码 Surface；不为旋转再次创建 VirtualDisplay。
- 接收端独立处理界面方向、源画面比例和 Surface 生命周期，Surface 重建后等待关键帧恢复。暂时离开接收页时继续排空数据，不累积待显示画面。
- 接收画面始终等比适配；全屏时以纯黑色填充剩余区域，非全屏时沿用当前页面的浅色或深色主题背景。
- 全屏进入时显示控件，默认空闲 3 秒后以 300 ms 动画淡出；点按画面切换控件显示，按住画面或聚焦控件时暂停隐藏，并遵循系统无障碍显示时长设置。

## 验证与真机联调

自动化覆盖邀请编码、过期、随机性、认证角色区分、跨连接重放拒绝、畸形视频包、NDEF 解析、NFC 清单入口、手动加入、方向确认、授权按钮与全屏布局。AVC 回环测试使用实际 MediaCodec 编码结果，经生产帧协议和生产解码器，验证竖屏、横屏及 Surface 更换后的图像输出。另有真实 MediaProjection 回环测试，经生产采集、编码、帧协议和解码器，验证同一次录屏会话内的旋转。录屏测试宿主只进入 debug 构建；测试用 AppOp 授权在结束时恢复，不属于产品授权流程。

发布前仍需两台目标真机完成以下联调；模拟器的编解码回环不等同于真实 NFC 和无线投屏：

- A 邀请 B，分别测试系统冷启动唤起、应用内主动加入、普通读卡页手动加入；交换邀请方再测试。
- 关闭 NFC 或使用不支持 NFC 的设备，端对端连接后直接进入屏幕共享；交换发起端，测试同时进入、仅一端进入、验证码不一致或只确认一端、等待超时及连接中断。
- 分别测试 A 向 B、B 向 A，取消方向请求、拒绝请求、双方同时提出方向、取消录屏授权、结束后重新授权及切换方向。
- 在完整屏幕和单应用共享中旋转源端，独立旋转接收端，进入与退出全屏，检查画面比例和恢复情况。
- 返回桌面使用其他应用、通知栏停止、系统录屏提示停止、锁屏、任务移除、Wi-Fi / 蓝牙关闭及断线，检查资源释放与提示。
- 让邀请自然过期、使用旧邀请或不同邀请连接，确认不会进入录屏流程。
- 连续共享至少 10 分钟，记录实际画面延迟、流畅度、温升和耗电；编码参数及模拟慢速反馈测试不作为真实无线链路的性能承诺。

当前范围不包含音频、远程输入和独立扩展桌面。受保护窗口可能显示空白；系统锁屏或收回录屏权限后，本次共享结束。
